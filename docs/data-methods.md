# 데이터 라벨링 방법

이 문서는 원본 수집·전처리, 표본 선정과 개발 노출 관리, 원본 프레임과 재생 시각의 연결, 라벨 작성·검수·수정 절차를 설명한다. 형식별 사용본 수량과 검수 결과는 [결과 보고서](../reports/medication-drinking/project-results.md), 항목의 뜻은 [라벨·분석 항목 안내](analysis-label-guide.md)에 있다.

## 1. 수집과 전처리

- **원본 계보.** 라벨 대상은 ETRI 리빙랩과 로봇환경의 RGB 영상이다. 기존 데이터 보관 범위에는 AI-Hub 일상생활 영상과 자체 촬영 영상도 있으며, 자체 촬영 영상은 개발용 영상 목록에만 쓰였다. 정리 전 ETRI RGB는 121,242개(리빙랩 8,622·로봇환경 112,620)다. 원본 보관본과 분류 사본을 경로·크기로 대조해 정리 범위를 확인했다.
- **분류 정리.** 원본을 기존 행동 분류 폴더로 정리하고 대응 목록(manifest)에 원본과 분류 사본의 경로, 출처, 참여자 코드, 크기를 남겼다. 복약(A003)과 물마시기(A004)를 우선 대상으로 하고, 음식 먹기·물 따르기·양치·얼굴 만지기처럼 혼동하기 쉬운 분류를 함께 다뤘다. 폴더와 파일명의 행동 코드는 선정에 쓰는 목록 정보이며 행동의 정답이 아니다.
- **식별.** 영상마다 행동명과 무관한 고정 ID를 부여하고 원본 바이트의 SHA-256을 기록했다. 같은 원본의 다른 위치는 별칭과 계보로 남겨 중복 등록을 막았다.
- **공통 형식 준비.** 등록 원장(dataset-index)의 ID·SHA-256에 프레임 대응표(frame-map)를 연결하고, 원본 해상도의 전 프레임 PNG와 원본 PTS를 준비했다. 재생 사본은 재인코딩 없이 비디오 패킷을 유지하고 PTS 원점만 맞췄다. 이전 도구에서 옮겨 온 영상은 기존 PNG와 원본 시각 정보를 바이트 그대로 보존했다. 디코딩과 이미지 준비는 관찰과 별도로 기록하며, 준비 완료를 관찰 완료로 보지 않는다.
- **시점 라벨 준비.** 날짜별 묶음에서 기존 원본 SHA-256과 경로·크기 정보를 재사용하고 현재 파일의 존재와 크기를 확인했다. 원본을 다시 해시하지 않았고, 이전 라벨의 판단은 사용하지 않았다.

## 2. 원본 프레임과 재생 시각의 연결

공통 형식은 `dataset-index → frame-map → revision`으로 연결된다. frame-map은 0부터 시작하는 프레임 번호를 원본 PTS(`source_ms`)와 PNG 파일에 연결한다. 원본의 첫 PTS는 0이 아닐 수 있으며, 재생 경과시간은 `player_elapsed_ms = source_ms − first_source_ms`로 계산한다. 예를 들어 첫 PTS가 160 ms이고 근거 프레임의 PTS가 1,860 ms이면 재생 위치는 1,700 ms다.

- 공통 형식의 구간과 근거는 원본 PTS로 저장하며 해당 프레임의 지도 값과 정확히 일치해야 한다. 구간의 끝(END)은 마지막으로 포함되는 프레임이다.
- 시점 라벨은 재생 경과시간(`PLAYER_ELAPSED_MS`)을 시간축으로 쓰고 `source.first_source_ms`를 함께 남긴다. 원본 프레임으로 돌아갈 때는 이 값을 더해 원본 PTS를 찾는다.
- 프레임 첫·끝 PTS의 차이는 관찰한 표본 시각의 범위이며, 마지막 프레임 길이를 포함한 컨테이너 길이와 구분한다.
- 원본 위치는 데이터 루트 기준 상대경로로 기록한다. 분류 사본이면 대응 목록의 목적지 경로에서 원본 상대경로를 찾는다. 로컬에 복원하지 않은 RGB 원본은 원본 상대경로와 백업 ZIP 이름 후보로 연결한다. 예를 들어 로봇환경 `RGB videos/P001-P010/P001/example/video.mp4`의 후보는 `RGB_P001-P010.zip`이다. 실제로 쓰기 전에 ZIP 내부 경로와 파일 SHA-256을 대조한다.

연결 필드는 [공통 저장 규약](../schemas/README.md#dataset-indexjsonl--frame-mapjson--revision)과 [시점 라벨 형식](../schemas/event-spot.md)에 있고, 가상 자료는 [합성 예제](../examples/README.md)에서 확인할 수 있다.

## 3. 표본 선정과 개발 노출

- 선정 단계의 미리보기는 가시성 확인용이며 라벨 관찰이 아니다.
- 출처별 참여자 코드는 그룹을 대조하는 단서다. 같은 사람 여부, 독립 촬영 여부, 기록되지 않은 개발 노출은 따로 확인해야 한다.
- 개발에 사용한 영상은 노출 상태를 남긴다. 개발용 인수본으로 발행한 영상은 개발 노출로 기록한다. `NOT_KNOWN_EXPOSED`는 알려진 노출이 없다는 뜻이며 미노출을 확인했다는 뜻이 아니다.
- 이 작업에서는 공식 학습·검증·시험 분할과 성능 평가를 하지 않았다.

## 4. 라벨 작성·검수·수정

### 4.1 공통 형식 (v0.1, v0.2)

1. **관찰.** 원본 해상도로 전 프레임을 관찰한다. 한 번에 최대 12장을 보고 앞 묶음과 2장씩 겹치게 넘긴다. 실제 표시 해상도, 프레임 범위, 관찰자와 기록 시각을 관찰 로그에 남긴다.
2. **작성.** 공통 작성 세션에서 하나의 양식으로 분석 8항목과 라벨을 함께 작성한다. 영상별 전용 양식이나 빈 초안 파일은 만들지 않는다. 미완성 작업은 영상별 최신 체크포인트 하나에 두고, 재개할 때 이미 관찰한 프레임을 반복하지 않는다.
3. **검사와 저장.** 형식, 필수 항목, 관찰 범위, 프레임과 PTS의 연결을 검사한 뒤 분석과 라벨을 같은 revision에 저장한다. 첫 유효본은 `revision-000000.json`이고, 실제로 내용이 바뀔 때만 다음 번호로 저장한다. 내용이 같으면 저장하지 않는다. 이전 revision은 덮어쓰지 않는다.
4. **검수.** 사용자가 공통 형식 85개의 검수를 완료했다. v0.2는 검수 화면의 단일 저장으로 수정 내용과 사용자가 선택한 검수 상태·검수자를 한 revision에 기록한다. 검수 완료를 선택하면 검수자, 서버 시각, 확인한 범위가 남는다. v0.1 21개의 검수 완료는 사용자의 직접 확인을 근거로 원본 작업공간의 작업 기록에 남겼고, 라벨 파일의 검수 필드는 저장 당시 값을 유지한다. 검수 후 내용을 고치면 재검토 규칙에 따라 다시 검수 대상이 된다.
5. **v0.2 재작성.** v0.1 기록이 있는 영상도 새 기준으로 다시 관찰해 분석과 라벨을 작성했다. v0.1 부분은 기준 revision의 읽기 전용 이력으로 남기고, 옛 답변이나 검수 상태를 새 의미로 옮기지 않았다.

### 4.2 시점 라벨

1. **작성.** 영상 전체를 약 1초 간격 표본(축소 표시)으로 훑고, 행동 후보 주변은 원본 해상도 프레임으로 확인했다. 일부 영상은 원본 전 프레임을 관찰했다. 저장본의 `observation`에 실제 관찰 방식과 범위를 남겼다. 행동 종류, 재생 경과시간 기준 시작·종료, 경계의 확실성을 기록하고, 보이지 않는 경계는 비워 두었다. 시작과 끝이 모두 정해진 구간에서는 시작이 끝보다 앞서야 하며, 끝은 마지막 포함 프레임이다.
2. **경계 확인.** 검수·수정 과정에서 경계를 다시 확인할 때는 전체 250 ms 간격 원본 표본, 후보와 앞뒤 1초의 100 ms 간격 표본, 시작·끝 주변 500 ms의 연속 프레임을 사용했다. 이미 관찰한 범위는 다시 보지 않고 재사용했다. 손이나 용기의 이동·회수와 입으로 가져가는 동작을 구분했다.
3. **수정 저장.** 수정한 내용은 새 revision으로 저장하고 이전 revision을 보존했다.
4. **검수.** 사용자가 389개 전수를 직접 확인했고, 복약·물마시기 영상의 경계를 모두 다시 확인했다. 행동 구간을 확인하면서 구간 수도 함께 확인했다. 이 확인은 원본 작업공간의 작업 기록에 남겼다. 라벨 파일의 검수 필드는 저장 당시의 값으로 두고 사후에 고치지 않았다.

시점 라벨은 읽기 전용 화면에서 구간을 선택해 재생하며 확인할 수 있다. 실행 방법은 [README](../README.md#로컬-원장-조회)에 있다.

### 4.3 공통 원칙

- 답변은 YES·NO·UNKNOWN과 빈 값을 구분한다. 보이지 않음을 NO로 바꾸지 않으며, UNKNOWN에도 실제로 관찰한 근거와 한계를 남긴다.
- 파일명이나 손이 입에 다가가는 동작만으로 약 식별이나 복용을 확정하지 않는다.
- 전달용 파일은 사용자가 저장된 revision을 골라 내보낼 때만 만든다.

## 5. 도구와 자료 위치

- 2026-10-17 기존 복약 영상 분석 파이프라인 프로젝트에서 프레임·PTS 매핑, 검수 화면, 기록 검증 함수를 골라 옮겼다. CVAT 전송, 고정 선택 목록, 자동 내보내기, 과거 판정은 가져오지 않았다. 검증 함수의 원본 파일과 함수별 지문은 [reuse-provenance.json](reuse-provenance.json)에 있다. 시점 라벨 화면은 이 작업공간에서 새로 만들었다.
- 실제 영상, 라벨 전문, 원본 대응 목록, 체크포인트, 검수 원장과 개인 설정은 원본 작업공간의 로컬 영역에만 둔다. 공개 저장소에는 방법, 규격, 도구 소스, 합성 예제와 집계 보고서를 둔다.
